# Knowledge refresh (offered, never imposed)

**The mode.** A knowledge dir (the resolver's output) that is `knowledge.legacyDir` is **private mode** whatever git says, as the generator rules. Otherwise the mode is read from the first line of the drift tool's output, computed once in `preflight.md` → "Drift": the `none` state ("Knowledge baseline: none — the knowledge is not committed in this branch.") is **private mode**; any other line is **committed mode**, where the knowledge belongs to the whole team and only `/generate-knowledge refresh`, run by whoever maintains the knowledge, writes it. `not computed` is **mode unknown**: no offer at Step 0 and no knowledge option at close; one line names `/generate-knowledge` for the developer to run (it finds its own mode), and with a `knowledge.required` file missing the run stops, naming the files and `/generate-knowledge`.

**The release branch** (committed mode only) is the `branch` record (`branch<TAB><name>`) of `bash .claude/{knowledge.drift} --list`, run from the project root once per run, the first time this file needs it; no such record, no branch.

Two moments, Step 0 and close.

## Private mode

**Step 0.** When the hook said `<TEAM-INBOX-DUE>` or `<TEAM-KNOWLEDGE-SCAFFOLD>`, or when Step -1 found a `knowledge.required` file missing: before any research and before the marker is written, one AskUserQuestion in the task's language — "Knowledge: {inbox due: N marks, R rows | scaffold knowledge on a project with content | missing: <files>}. Refresh now (a few minutes, then the run continues) / Continue without it." One question covers every reason present at once. Two exceptions: with required files missing, "Continue without it" is not on offer — the run cannot start without knowledge, so the options are "Generate now" and "Stop", and on stop the missing files are named; and when `checks.knowledgeScaffold` prints `project: empty`, offer nothing — the generator's empty-project path asks the developer which stack is decided, which a subagent cannot answer — and name `/generate-knowledge` for the developer to run. A parked run whose marker is still `state=open` gets no offer either; the generator would refuse it. `learnings-check.md` runs after the marker is written, so it only records `deferred to close`; the closing question carries that offer.

**Close.** The "Closing" question in SKILL.md carries the option **refresh knowledge now — N files, M marks** when the Reviewer's `Learning:` line wrote a `[STALE-CHECK]` or `[PROMOTE]` mark in this run, when the inbox was due at Step 0 and the developer declined then, or when `learnings-check.md` recorded `deferred to close`. It is asked after `status.md` is `[DONE]` and the marker is `state=closed`, never before.

## Committed mode

A run never writes knowledge, never offers the refresh and never runs it.

**Step 0.** `<TEAM-INBOX-DUE>` → before any research and before the marker is written, one AskUserQuestion in the task's language: "Inbox: N marks, R entries. Triage it now (your remarks are offered for submission) / Continue" — N the pending marks and R the entries of the inbox check's first line, as the hook quotes it. Scaffold knowledge on a project with content (`<TEAM-KNOWLEDGE-SCAFFOLD>`, or `checks.knowledgeScaffold` exit 1) → no offer, one line: the knowledge is a scaffold, and `/generate-knowledge refresh` regenerates it. A `knowledge.required` file missing → no offer: the run stops, naming the missing files and `/generate-knowledge refresh`; nothing is generated by a run. A parked run whose marker is still `state=open` gets no offer, as in private mode.

**Close.** The "Closing" question carries the option **pass on what this run met — N remarks → <branch>** when the Reviewer's `Learning:` line wrote an entry or a mark in this run, when the inbox was due at Step 0 and the developer declined then, or when `learnings-check.md` recorded `deferred to close`. N counts the entries and marks the `Learning:` lines reported in this run, plus the pending marks of the inbox check when the inbox was due; the triage decides what is submitted. With no release branch the option reads **triage the inbox**, and nothing is submitted. It is asked after `status.md` is `[DONE]` and the marker is `state=closed`, never before.

## Running it

On yes, at either moment: one Agent call, with no handoff envelope (the generator is a command, not a role) and `model` omitted. Prompt in private mode:

> You are the Knowledge Generator. Read `.claude/skills/generate-knowledge/SKILL.md` and follow it. Arguments: `Consent: given`. Answer in {language}. Ask no question; report the work list as done, the backup path and the size table.

In committed mode (with no release branch, `Branch: <branch>` is left out of the arguments):

> You are the Knowledge Generator. Read `.claude/skills/generate-knowledge/SKILL.md` and follow it. Arguments: `Consent: given`, `Branch: <branch>`. Answer in {language}. Ask no question; report the work list as done, the backup path, and the output of the proposals tool verbatim.

Scope: no file names at either moment. The generator's own staleness check and inbox classification find exactly the files and marks this run left behind, and a file-name run would skip the triage the option promises. The marker stays as it is. At Step 0 the call is made before the marker is written, because a marker in `state=open` is the one case the generator skips its shape work and triage for; at close the marker is already `state=closed`, which it accepts. Never run the generator while a marker says `state=open`, and never delete a marker to make room for it.

## Recording it

- `## Decisions log`, private mode: `{YYYY-MM-DD} — Knowledge refreshed by the team: {files | all}, {M} marks triaged; backup {path from the generator's report}`.
- `## Decisions log`, committed mode: `{YYYY-MM-DD} — Remarks submitted by the team: {N} on {new branch}; push and pull request left to the developer`, N and the new branch from the tool's `proposals:` line. The final report repeats the tool's `push:` and `pull request:` lines verbatim. When nothing was submitted, the line reads `{YYYY-MM-DD} — Inbox triaged by the team; nothing submitted: {the reason the generator reported}`.
- `## Process notes`: `Inbox due: offered YYYY-MM-DD — refreshed | triaged | declined` (mode unknown: `Inbox due: told YYYY-MM-DD`) or `Scaffold knowledge: offered YYYY-MM-DD — refreshed | declined` (committed mode or mode unknown: `Scaffold knowledge: told YYYY-MM-DD`), one line, written once. A resumed session that finds the line says nothing more about it.

On no, the run continues; nothing is repeated on resume. Never block a run on knowledge, except for the stop on missing required files above.
