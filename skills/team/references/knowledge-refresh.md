# Knowledge refresh (offered, never imposed)

**The mode.** A knowledge dir (the resolver's output) that is `knowledge.legacyDir` is **private mode** whatever git says, as the generator rules. Otherwise the mode is read from the first line of the drift tool's output, computed once in `preflight.md` → "Drift": the `none` state ("Knowledge baseline: none — the knowledge is not committed in this branch.") is **private mode**; any other line is **committed mode**, where the knowledge belongs to the whole team and only `/generate-knowledge refresh`, run by whoever maintains the knowledge, writes it. `not computed` is **mode unknown**: no offer at Step 0 and no knowledge option at close; one line names `/generate-knowledge` for the developer to run (it finds its own mode), and with a `knowledge.required` file missing the run stops, naming the files and `/generate-knowledge`.

Two moments, Step 0 and close. The remarks themselves are offered at the close in both modes, by SKILL.md → "Closing"; this file is about the knowledge.

## Private mode

**Step 0.** When the hook said `<TEAM-INBOX-DUE>` or `<TEAM-KNOWLEDGE-SCAFFOLD>`, or when Step -1 found a `knowledge.required` file missing: before any research and before the marker is written, one AskUserQuestion in the task's language — "Knowledge: {remarks due: N marks, R rows | scaffold knowledge on a project with content | missing: <files>}. Refresh now (a few minutes, then the run continues) / Continue without it." One question covers every reason present at once. Two exceptions: with required files missing, "Continue without it" is not on offer — the run cannot start without knowledge, so the options are "Generate now" and "Stop", and on stop the missing files are named; and when `checks.knowledgeScaffold` prints `project: empty`, offer nothing — the generator's empty-project path asks the developer which stack is decided, which a subagent cannot answer — and name `/generate-knowledge` for the developer to run. A parked run whose marker is still `state=open` gets no offer either; the generator would refuse it. `learnings-check.md` runs after the marker is written, so it only records `deferred to close`; the closing question carries that offer.

**Close.** The "Closing" question in SKILL.md carries the option **refresh knowledge now — N files, M marks** when a remark this run added to the remarks dir carries a `[STALE-CHECK]` or `[PROMOTE]` mark, when the remarks were due at Step 0 and the developer declined then, or when `learnings-check.md` recorded `deferred to close`. It is asked after `status.md` is `[DONE]` and the marker is `state=closed`, never before, and after the remarks were accepted or declined: the generator's triage reads the remarks dir, so it sees what the developer accepted. When the closing question offers remarks, this option is not on it; it is asked as an AskUserQuestion of its own once the remarks are settled, and only when it still applies.

## Committed mode

A run never writes knowledge, never offers the refresh and never runs it. There is no question and no notice about remarks at Step 0: a developer cannot act on them, and the lead's reminder is the drift line (`Proposals: <N> waiting, the budget is <M>: a refresh is due.`).

**Step 0.** Scaffold knowledge on a project with content (`<TEAM-KNOWLEDGE-SCAFFOLD>`, or `checks.knowledgeScaffold` exit 1) → no offer, one line: the knowledge is a scaffold, and `/generate-knowledge refresh` regenerates it. A `knowledge.required` file missing → no offer: the run stops, naming the missing files and `/generate-knowledge refresh`; nothing is generated by a run.

## Running it

Private mode only. On yes, at either moment: one Agent call, with no handoff envelope (the generator is a command, not a role) and `model` omitted. Prompt:

> You are the Knowledge Generator. Read `.claude/skills/generate-knowledge/SKILL.md` and follow it. Arguments: `Consent: given`. Answer in {language}. Ask no question; report the work list as done, the backup path and the size table.

Scope: no file names at either moment. The generator's own staleness check and the triage of the remarks dir find exactly the files and marks this run left behind, and a file-name run would skip the triage the option promises. The marker stays as it is. At Step 0 the call is made before the marker is written, because a marker in `state=open` is the one case the generator skips its shape work and triage for; at close the marker is already `state=closed`, which it accepts. Never run the generator while a marker says `state=open`, and never delete a marker to make room for it.

## Recording it

- `## Decisions log`: `{YYYY-MM-DD} — Knowledge refreshed by the team: {files | all}, {M} marks triaged; backup {path from the generator's report}`.
- `## Process notes`: `Inbox due: offered YYYY-MM-DD — refreshed | declined` (mode unknown: `Inbox due: told YYYY-MM-DD`) or `Scaffold knowledge: offered YYYY-MM-DD — refreshed | declined` (committed mode or mode unknown: `Scaffold knowledge: told YYYY-MM-DD`), one line, written once. A resumed session that finds the line says nothing more about it.

On no, the run continues; nothing is repeated on resume. Never block a run on knowledge, except for the stop on missing required files above.
