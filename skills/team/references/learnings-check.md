# Learnings check (every workflow except Docs, before any Brainstorm or research)

Run `bash .claude/tools/learnings-index.sh "<remarks dir>"` from the project root, `<remarks dir>` being the resolver's `remarks` output (`preflight.md` → "Directories"): the learnings index, one row per remark in the remarks dir, whether git tracks it yet or not (no remarks dir: no rows). Match rows whose title or tags overlap the task terms, then open every matched row with the Read tool at its `File` cell. Put their title + "Fix pattern" lines into every handoff's `prior learnings` field, and record the matched titles in status.md. The `team amendments` field beside it is filled from the collector, as `amendments.md` → "Active" says, not from the remarks dir.

Then, in private mode only (`knowledge-refresh.md` → "The mode"), run `checks.learningsInbox` as `checks.learningsInboxRunFrom` in `.claude/team-manifest.json` spells out. On exit 1, when status.md → "Process notes" carries no `Inbox due:` line yet (the hook's notice at Step 0 normally put one there), write `Inbox due: offered YYYY-MM-DD — deferred to close (<the check's first line>)`: the marker is already `state=open` here, so the generator cannot run now, and the closing question carries the knowledge option instead (`knowledge-refresh.md`). A resumed session that finds an `Inbox due:` line says nothing more about it. In committed mode, or with the mode unknown, nothing is run here and nothing is written about it: the lead's reminder is the drift line.

Never block the run on the remarks. The hook injects the same notice as `<TEAM-INBOX-DUE>` on the prompt that starts a run, in private mode only; it is the same offer, not a second one.
