# Learnings check (every workflow except Docs, before any Brainstorm or research)

Run `bash .claude/tools/inbox.sh index` from the project root: the learnings index, one row per entry. Match rows whose title or tags overlap the task terms, then run `bash .claude/tools/inbox.sh show <File> …` with the matched rows' `File` cells. Put their title + "Fix pattern" lines into every handoff's `prior learnings` field, and record the matched titles in status.md. The inbox is never read by a path or with a file tool: it may live outside the project. The `team amendments` field beside it is filled from the collector, as `amendments.md` → "Active" says, not from the inbox.

Then run `bash .claude/tools/inbox.sh check`. On exit 1, when status.md → "Process notes" carries no `Inbox due:` line yet (the hook's notice at Step 0 normally put one there), write `Inbox due: offered YYYY-MM-DD — deferred to close (<the check's first line>)`: the marker is already `state=open` here, so the generator cannot run now, and the closing question offers the refresh instead (`knowledge-refresh.md`). A resumed session that finds an `Inbox due:` line says nothing more about it.

Never block the run on the inbox. The hook injects the same notice as `<TEAM-INBOX-DUE>` on the prompt that starts a run; it is the same offer, not a second one. A `note:` line that `inbox.sh where` printed at preflight is said to the developer once.
