2. **Team files.**
2. **Team files.** The team is installed by `copilot/install.sh` from the team's own repository. It puts the agents in `.github/agents/`, the commands in `.github/skills/`, the session hook in `.github/hooks/dream-team.json` and everything else in `.github/dream-team/`, and lists what it wrote in `.github/dream-team/.installed`. For each name in `agents[]` verify `.github/agents/<name>.agent.md` exists and its frontmatter `name:` matches; for each in `skills[]` verify `.github/skills/<name>/SKILL.md`. For the `team` skill also verify that `.github/skills/team/references/` holds one file per workflow named in the marker block of the team skill (`analyze.md` … `full_feature.md`); a missing one is reported like a missing skill. Verify every template path under `templates` exists and that `templates.standards` and `templates.interface` each contain `_generic.md`. Verify too that every script the `checks` block names exists under `.github/dream-team/`, and so do `setup.normalizer`, `tracking.migration`, `knowledge.migration`, `knowledge.resolver`, and every tool the `knowledge` block names — `knowledge.learningsIndex`, `knowledge.remarks`, `knowledge.ruleExtractor`, `knowledge.drift` and `knowledge.refresh` — and the generator's reference `.github/skills/generate-knowledge/references/refresh.md`: a deployment that lost them passes every other test in this skill while a run silently cannot accept a remark and `/generate-knowledge` cannot verify its own work or refresh committed knowledge. Report anything missing by name; a missing file means an incomplete deployment, and the fix is to run `copilot/install.sh` again from a fresh copy of the team's repository, which this skill never does by itself.
